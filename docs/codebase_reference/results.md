# `results/` Directory Reference

This directory serves as the output destination for all experiments run within the URB environment. When you execute an experiment script (e.g., `centralized_dqn.py`, `baselines.py`), the script creates a dedicated subfolder here named after the `--id` (experiment identifier) provided at runtime.

## Directory Flow & Pipeline Consumption
1. **Creation (Training Scripts)**: Python scripts in `scripts/` create `results/<exp_id>/` and populate it with simulation parameters (`exp_config.json`) and raw telemetry (`episodes/` and `SUMO_output/`).
2. **Processing (`analysis/metrics.py`)**: Automatically scans the raw telemetry, compresses it, and emits synthesized statistics into `results/<exp_id>/metrics/`.
3. **Aggregation (`leaderboard/generate_leaderboard.py`)**: Scans all subdirectories in `results/`, reading the synthesized metrics and compiling them into the public HTML leaderboard.

---

## Deep Subdirectory Details & Data Structures

### 1. Configuration (`exp_config.json`)
A flattened JSON dictionary capturing exactly how the experiment was run. This is strictly required for reproducibility.
**Example Data Structure:**
```json
{
    "algorithm": "ippo_torchrl",
    "network": "saint_arnoult",
    "env_seed": 42,
    "torch_seed": 42,
    "human_learning_episodes": 3,
    "training_eps": 5,
    "test_eps": 1,
    "ratio_machines": 0.4,
    "script": "scripts/ippo_torchrl.py"
}
```

### 2. Raw Simulation Logs
These files are the immediate output of the simulation execution.

- **`episodes/` (CSV)**: Logged directly by `routerl`. Each CSV file represents a single simulation episode.
  - *Columns*: `agent_id`, `origin`, `destination`, `departure_time`, `action_taken`, `reward_received`.
- **`SUMO_output/` (XML)**: Logged directly by SUMO C++ bindings. The core file is `detailed_sumo_stats_<episode>.xml`.
  - *Snippet*:
  ```xml
  <tripinfos>
      <tripinfo id="34" depart="12.00" departLane="E1_0" departPos="5.10" departSpeed="0.00" departDelay="1.00" arrival="45.00" arrivalLane="E5_0" arrivalPos="100.00" arrivalSpeed="13.89" duration="33.00" routeLength="400.00" waitingTime="0.00" waitingCount="0" stopTime="0.00" timeLoss="4.20" rerouteNo="0" devices="tripinfo_34" vType="Machine" speedFactor="1.00" vaporized=""/>
  </tripinfos>
  ```
  *(Notice the `vType` determining if it was a Human or Machine, and `duration` which is extracted by `metrics.py` as the primary penalty signal).*

### 3. Algorithm Training Tracking
- **`losses/losses.csv`**: Emitted periodically by the PyTorch optimization loop inside the training script.
  - *Columns*: `iteration`, `loss`, `loss_entropy`, `loss_objective`, `loss_critic`.
  - Used to verify that the actor-critic networks are actually converging rather than oscillating wildly.

### 4. Post-Experiment Metrics (`metrics/`)
Generated by `analysis/metrics.py` after the experiment loop concludes.

- **`combined_data.csv`**: A pandas-generated file mapping every agent's telemetry across all episodes. The index is `episode`, and columns are flattened: `agent_0_duration`, `agent_1_duration`, etc.
- **`BenchmarkMetrics.csv`**: The scalar summary file.
  - *Data*: A single row containing metrics like: `t_pre` (pre-mutation travel time), `t_test` (final system travel time), `t_CAV` (travel time strictly for autonomous vehicles), `Cost of Learning`, `WinRate` (1 or 0).
- **`plots/`**: Automatically generated `matplotlib` `.png` files, primarily `travel_times.png` which charts the rolling average of travel times across the `human_learning`, `mutation_and_training`, and `testing` phases.
